---

## 一、项目一句话介绍（简历用）

**深度研究助手**：基于 FastAPI + Vue3 的多智能体 Web 应用。用户输入研究主题后，系统自动将其分解为 3-5 个子任务，并发调用搜索引擎采集资料，由三个 LLM Agent（规划/总结/报告）协作完成研究，并通过 SSE 实时流式推送进度与最终 Markdown 报告。

**技术栈**：Python、FastAPI、SSE、Vue3、TypeScript、Vite、OpenAI SDK（DeepSeek）、DuckDuckGo、多线程并发、Prompt Engineering、Agent 架构

---

## 二、项目整体流程（你必须能讲出来）

1. 用户在前端输入研究主题，点击开始研究
2. 前端 POST /research/stream 建立 SSE 流式连接
3. 后端 Planner Agent 将主题分解为 3-5 个子任务（JSON）
4. 每个子任务：SearchTool 搜索（DuckDuckGo）-> 格式化上下文 -> Summarizer Agent 流式生成总结
5. 子任务并发执行（多线程），进度通过 SSE 实时推给前端
6. 全部完成后 Report Writer Agent 整合所有总结生成最终报告
7. 前端实时展示：任务状态、来源列表、流式总结、最终报告

**项目名称：深度研究智能体助手（Deep Research Agent）**

**项目时间：2026年8月 | 独立开发 | Python / FastAPI / Vue3 / LLM**

**项目描述：**
开发了一个自动化深度研究 Web 应用：用户输入研究主题后，系统自动完成 任务规划、多源信息检索、内容总结、报告生成 全流程，并通过 SSE 实时推送研究进度，将原本 1-2 小时的人工研究压缩到 5-10 分钟。

**核心工作与亮点：**
1. **多智能体协作架构**：基于 HelloAgents 框架设计三个职责分离的 LLM Agent（任务规划器、总结器、报告撰写器），通过 System Prompt 定制各角色行为，实现 TODO 驱动的 规划-执行-报告 三阶段研究流水线，子任务并行执行提升效率。

4. **工程健壮性**：搜索失败自动降级为 LLM 先验知识生成；LLM 流式响应中断自动重试并回退非流式调用；多线程 + 事件队列实现子任务并发与有序输出。

**技术栈**：Python 3.10+、FastAPI、Uvicorn、Vue3、TypeScript、Vite、OpenAI SDK、DeepSeek API、DuckDuckGo、多线程、SSE

## 六、面试题库（必背）

### 6.1 项目介绍类
Q1: 介绍一下你这个项目是做什么的？
A: 一句话定位 + 核心流程 + 技术栈（参考第一章/第五章）

Q2: 为什么要做三个 Agent 而不是一个？
A: 职责分离、Prompt 定制、单一职责易维护、每个环节可单独优化/调试；类似工厂流水线，每道工序有专门工人

Q3: 整个数据流是怎样的？
A: 前端 POST /research/stream -> FastAPI -> DeepResearchAgent.run_stream -> Planner 拆解任务 -> 子任务并发(搜索+总结) -> 事件队列 -> SSE 推送 -> Reporter 生成报告 -> 前端渲染

### 6.2 技术原理类
Q4: SSE 和 WebSocket 有什么区别？为什么用 SSE？
A: SSE 单向服务器推送到客户端，基于 HTTP，自动重连，简单；WebSocket 双向全双工。本项目只需服务器推流进度，用 SSE 足够且简单

Q5: 为什么前端用 fetch 而不是 EventSource？
A: 本项目用 POST 传 JSON 请求体，EventSource 只支持 GET

Q6: 子任务是怎么并行的？
A: Python threading.Thread 每任务一个线程，事件写入 queue.Queue，主线程消费队列转发 SSE；注意 GIL 但本场景是 IO 密集（网络请求）所以有效

Q7: LLM 流式输出是怎么实现的？
A: openai SDK stream=True，迭代 response 拿 delta.content 逐块 yield

Q8: 搜索结果太多怎么办？
A: 去重(URL set) + 按 max_tokens 截断摘要，防止超上下文窗口

Q9: Prompt 里为什么要放当前日期？
A: 让模型知道时间上下文，搜索 query 可以带年份，获得最新信息

Q10: 搜索失败会怎样？
A: 降级策略：不中断任务，让总结 Agent 基于模型先验知识生成，并明确标注非实时信息

### 6.3 项目细节类
Q11: todo_list 事件和 task_status 事件有什么区别？
A: todo_list 是规划完成后的任务清单快照；task_status 是每个任务执行过程中的状态变更(in_progress/completed/failed)

Q12: sources 事件里 latest_sources 是什么？
A: 该任务搜索结果格式化后的来源摘要（标题+链接），供前端展示

Q13: 最终报告怎么生成的？
A: Reporter Agent 拿到所有任务的 summary + sources，按模板生成 背景/核心洞见/证据/风险/参考来源 五段式 Markdown

Q14: 笔记(NoteTool)的作用？
A: 任务状态持久化到 markdown 文件，支持断点恢复与审计追溯

Q15: .env 里哪些配置影响系统行为？
A: LLM_PROVIDER/LLM_MODEL_ID/LLM_API_KEY/LLM_BASE_URL 决定模型；SEARCH_API 决定搜索引擎；MAX_WEB_RESEARCH_LOOPS 决定迭代深度

## 七、本项目常见坑与规避（实战经验）

### 7.1 我们实际踩过的坑（已修复）

| 坑 | 现象 | 原因 | 解决 |
|----|------|------|------|
| DuckDuckGo 无结果 | 5 个子任务全 failed，无信息来源 | 新版 ddgs 库不支持 backend=duckduckgo 参数值，直接抛异常 | 去掉 backend 参数 + 3 次重试 + timeout 15s |
| LLM 流式中断 | peer closed connection without sending complete message body，子任务 failed | DeepSeek API 流式响应中途断开，原代码无重试 | 流式失败自动重试 3 次，失败后 fallback 非流式调用 |
| 代理网络问题 | connect ECONNREFUSED 127.0.0.1:7897 | 系统代理指向本地代理端口未启动 | 检查代理软件；或设置 NO_PROXY |
| 端口被占用 | Address already in use | 上次进程未退出 | taskkill /PID <pid> /F |
| Windows reload 不稳定 | uvicorn reload 卡死 | Windows 下 reload 有已知问题 | reload=False，手动重启 |

### 7.2 面试时可讲的优化方向（体现思考深度）

1. **并发控制**：当前每任务一线程，可改为线程池(ThreadPoolExecutor)限制最大并发，避免搜索 API 限流
2. **结果缓存**：相同 query 的搜索结果缓存到磁盘，节省 API 调用与时间
3. **断线重连**：前端 SSE 断流时自动重连并从中断点续传（当前未实现）
4. **上下文管理**：长期研究可通过 NoteTool 笔记实现跨会话恢复
5. **质量评估**：给规划质量打分（子任务数量/查询质量），参考书中 evaluate_plan
6. **多模型支持**：支持 Ollama 本地模型 / LM Studio，数据不出本机
