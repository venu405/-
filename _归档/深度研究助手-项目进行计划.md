## 一、项目整体流程讲解

### 1.1 这是什么项目

这是一个 **深度研究助手（Deep Research Agent）**，用户输入一个研究主题，系统自动完成：

1. **规划任务**：LLM 将主题拆解为 3-5 个互补的子任务
2. **并行搜索**：每个子任务独立进行网络搜索（DuckDuckGo），收集信息来源
3. **流式总结**：每个子任务用 LLM 生成结构化总结，实时流式输出给前端
4. **生成报告**：汇总所有子任务结果，LLM 生成最终结构化研究报告

### 1.2 技术架构总览

```
用户浏览器 (Vue3 前端, port 5174)
    |  POST /research/stream (SSE 流式)
    v
FastAPI 后端 (port 8000)
    +-- DeepResearchAgent (协调器)
    |     +-- PlanningService -> 调用 LLM 规划任务
    |     +-- 并发执行 N 个子任务 (Thread)
    |     |     +-- dispatch_search() -> SearchTool -> DuckDuckGo
    |     |     +-- SummarizationService -> 调用 LLM 流式生成总结
    |     +-- ReportingService -> 调用 LLM 汇总最终报告
    +-- hello_agents 库 (LLM封装, Agent框架, SearchTool, NoteTool)
```

### 1.3 后端关键流程（agent.py 的 run_stream 方法）

```
1. 用户提交研究主题
2. PlanningService.plan_todo_list()
   -> 调用 研究规划专家 Agent (LLM)
   -> 解析返回的 JSON，得到 3-5 个 TodoItem (含 title/intent/query)
3. 前端收到 todo_list 事件，渲染任务清单
4. 并发启动多个 Thread，每个执行子任务：
   a. dispatch_search(task.query) -> DuckDuckGo API -> 返回搜索结果
   b. prepare_research_context() -> 格式化搜索结果为结构化 context
   c. stream_task_summary() -> LLM 流式生成 Markdown 总结 -> SSE 实时推送
5. 所有子任务完成后 -> ReportingService.generate_report() -> 最终报告
6. 最终报告通过 SSE 推送给前端，流程结束
```

### 1.4 前端关键流程（App.vue）

```
1. 用户输入研究主题 -> 点击 开始研究
2. 调用 api.ts runResearchStream() -> fetch POST /research/stream -> ReadableStream 读 SSE
3. 逐条处理事件：
   - status -> 进度日志 | todo_list -> 渲染任务清单
   - task_status -> 更新状态 | sources -> 更新来源列表
   - task_summary_chunk -> 追加总结 | final_report -> 显示报告 | done -> 结束
4. 界面实时更新：任务清单 / 来源 / 总结 / 报告
```

## 五、核心代码速查（面试前必看）

### 5.1 后端启动入口 main.py

```python
# POST /research/stream 是核心接口，返回 SSE 流
@app.post("/research/stream")
def stream_research(payload: ResearchRequest) -> StreamingResponse:
    agent = DeepResearchAgent(config=Configuration.from_env())
    def event_iterator():
        for event in agent.run_stream(payload.topic):
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
    return StreamingResponse(event_iterator(), media_type="text/event-stream")
```

### 5.2 核心协调器 agent.py 的 run_stream

```python
# 1. 规划阶段
state.todo_items = self.planner.plan_todo_list(state)
# 2. 并发执行：每任务一个线程，事件写入 Queue
def worker(task, step):
    for event in self._execute_task(state, task, emit_stream=True, step=step):
        enqueue(event, task=task)  # 写入队列
thread = Thread(target=worker, args=(task, step), daemon=True)
thread.start()
# 3. 主线程消费队列 -> yield 给 SSE
while finished_workers < active_workers:
    event = event_queue.get()
    yield event
# 4. 报告阶段
report = self.reporting.generate_report(state)
yield {"type": "final_report", "report": report}
```

## 六、本项目中的三个 Agent 角色速览

| Agent | 中文名 | 职责 | Prompt 关键点 | 输出 |

## 七、面试常见问题速答（详细版见 7天计划 第六章）

1. 项目核心价值？ -> 将 1-2 小时人工研究压缩到 5-10 分钟，多智能体自动完成 规划-搜索-总结-报告
2. 为什么三个 Agent？ -> 职责分离、Prompt 定制、易维护、每环节可独立优化
3. SSE vs WebSocket？ -> SSE 单向、基于 HTTP、自动重连；本项目只需要服务器推流
4. 为什么 fetch 不用 EventSource？ -> 需要 POST 传 JSON 请求体
5. 并发怎么实现？ -> 每任务一个线程 + Queue 事件队列，IO 密集型场景有效
6. 搜索失败？ -> 降级为 LLM 先验知识，不中断流程
7. LLM 流式中断？ -> 重试 3 次 + fallback 非流式
8. 结果太多？ -> 去重 + Token 截断
9. Prompt 为什么放日期？ -> 让模型带上时间上下文搜索最新信息
10. 可以换模型吗？ -> 改 .env：LLM_PROVIDER/LLM_MODEL_ID/LLM_API_KEY
