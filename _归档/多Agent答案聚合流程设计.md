# 多 Agent 协作答案聚合流程设计

> 目标：将 5 个子 Agent 分别生成的结果，整合为一份完整、结构化的最终报告。
> 核心思路：**先独立提炼 → 再交叉比对 → 最后主编合成**（三层流水线）。

---

## 一、流程架构总览

```
输入：5 个子 Agent 输出（S1-S5）
  │
  ▼
【第 1 层 · 独立摘要层】—— 5 个摘要 Agent 并行（工厂模式，互不串话）
  每个输出 → 独立摘要 Agent → {核心观点[], 关键数据[], 主要结论[]}
  │
  ▼
【第 2 层 · 交叉分析层】—— 1 个对比 Agent
  全部摘要 → {重复信息[], 关联点[], 分歧点[]}（均标注 Agent 编号）
  │
  ▼
【第 3 层 · 报告合成层】—— 1 个主编 Agent
  摘要 + 交叉分析 → 四层结构报告（模板控制）
  │
  ▼
输出（缺一不可）：
  ① 各子 Agent 总结摘要（独立区块 × 5，先呈现）
  ② 合并后完整报告（四层结构，后呈现）
```

---

## 二、三层架构详解

### 第 1 层 · 独立摘要层（5 个并行摘要 Agent）

**输入**：每个子 Agent 的完整输出
**输出**：5 份结构化 JSON

```json
{
  "core_points": ["核心观点1", "核心观点2", ...],
  "key_data": ["关键数据1", ...],
  "conclusions": ["主要结论1", ...]
}
```

**设计要点**：
1. **工厂模式创建**：每个摘要 Agent 独立创建、用完清历史——防止任务间串话（与项目 summarizer 的 `_agent_factory()` 同原理）
2. **并行执行**：5 个并发线程，总耗时 ≈ 最慢的一个，不排队
3. **结构化输出**：强制 JSON 格式，供下一层程序化处理（与项目 `todo_planner_instructions` 的 JSON 模板同思路）

### 第 2 层 · 交叉分析层（1 个对比 Agent）

**输入**：5 份摘要
**输出**：交叉分析 JSON

```json
{
  "duplicates": ["重复内容（Agent 2/4 均提及）", ...],
  "agreements": ["共识结论（Agent 1/3/5 一致认可）", ...],
  "disagreements": ["分歧内容（Agent 2 说 X，Agent 5 说 Y）", ...]
}
```

**设计要点**：
1. 所有条目**标注 Agent 编号**——可追溯
2. 去重信息供第 3 层"只保留一处"（防重复出现 5 遍）
3. 共识点提升可信度；分歧点如实呈现（不隐藏矛盾）

### 第 3 层 · 报告合成层（1 个主编 Agent）

**输入**：5 份摘要 + 交叉分析结果
**输出**：四层结构最终报告（Markdown）

```
# 开篇总览
  研究主题 + 3-5 条核心发现（先给结论）

# 各子 Agent 分区详解
  ## 子 Agent 1：主题概述
     （标注来源：查询词 + 链接）
  ## 子 Agent 2：...
  ...共 5 个分区

# 跨 Agent 对比分析
  ## 共识点（关联点）
  ## 分歧点

# 综合结论
  综合判断 + 建议
```

**设计要点**：
1. **固定模板控制结构**（与项目 report_writer_instructions 的 REPORT_TEMPLATE 同思路）
2. **每分区标注来源**——可追溯
3. **禁止封面结语、信息缺失写"暂无相关信息"**——防废话、防捏造

## 三、提示词设计（可直接使用）

### 3.1 摘要 Agent 提示词（第 1 层，每份输出一份）

```
你是一名内容摘要专家。请对下面的子 Agent 输出进行独立总结。

【子 Agent N 完整输出】
（原文粘贴处）

请提取：
1. 核心观点：3-5 条，每条不超过 30 字
2. 关键数据：如有数字/指标，逐条列出（没有就写"无"）
3. 主要结论：1-3 条，必须能从原文中找到依据

只输出 JSON：{"core_points": [...], "key_data": [...], "conclusions": [...]}
```

### 3.2 对比 Agent 提示词（第 2 层，一份）

```
你是一名跨来源分析专家。以下是 5 个子 Agent 的摘要：

【Agent 1】...（摘要粘贴处）
【Agent 2】...
【Agent 3】...
【Agent 4】...
【Agent 5】...

请分析三类内容，每条都标注涉及的 Agent 编号（如"Agent 2/4"）：
1. 重复信息：多个 Agent 都提到的相同内容
2. 关联点：多个 Agent 一致认可、可互相印证的结论
3. 分歧点：Agent 之间说法矛盾或差异较大的内容

只输出 JSON：{"duplicates": [...], "agreements": [...], "disagreements": [...]}
```

### 3.3 主编 Agent 提示词（第 3 层，一份）

```
你是一名资深报告主编。请基于以下材料撰写结构化研究报告：

【5 份摘要】
（各摘要粘贴处）

【交叉分析结果】
（duplicates / agreements / disagreements 粘贴处）

<REPORT_TEMPLATE>
1. 开篇总览：研究主题 + 3-5 条核心发现（先给结论）
2. 各子 Agent 分区详解：每区标题为「子 Agent N：主题概述」，
   内容必须标注来源（Agent 编号 + 查询词 + 链接）
3. 跨 Agent 对比分析：分"共识点"和"分歧点"两小节，
   每条标注涉及的 Agent 编号
4. 综合结论：综合各 Agent 判断，给出最终结论与建议
</REPORT_TEMPLATE>

<REQUIREMENTS>
- 使用 Markdown 分级标题；禁止封面和结语；
- 重复信息只保留一处；信息缺失写"暂无相关信息"；
- 禁止残留 [TOOL_CALL:...] 指令
</REQUIREMENTS>
```

## 五、与现有项目的映射（升级路径）

### 现状（单 Agent 汇总）

```python
# reporter.py（现有）
report = self.reporting.generate_report(state)
# 一个报告 Agent 把 5 个任务总结直接汇总成报告，1 次 LLM 调用
```

### 升级（三层流水线）

```python
# 新增 services/aggregator.py
class AggregationService:
    def __init__(self, summarizer_factory, compare_agent, editor_agent):
        ...

    def aggregate(self, agent_outputs: list[dict]) -> tuple[list[dict], str]:
        # ① 第 1 层：5 个摘要 Agent 并行
        summaries = self._summarize_all(agent_outputs)   # 返回 5 份 JSON
        # ② 第 2 层：交叉分析
        cross = self._compare(summaries)                 # 返回去重/共识/分歧
        # ③ 第 3 层：主编合成
        report = self._compose(summaries, cross)         # 返回四层报告
        return summaries, report                         # 摘要 + 报告，缺一不可
```

### 对比表

| 维度 | 现在（单 Agent） | 新设计（3 层流水线） |
|------|-----------------|---------------------|
| LLM 调用次数 | 1 次 | 5 + 1 + 1 = 7 次 |
| 来源可追溯 | 弱 | 强（每分区标注来源） |
| 重复内容 | 可能重复 | 交叉分析层去重 |
| 分歧处理 | 无 | 显式标注 |
| 独立摘要输出 | 无 | 有（第一部分） |
| 耗时 | 快 | 慢（约 1-2 分钟） |
| 报告质量 | 中等 | 高（结构化 + 可追溯） |

## 六、面试弹药

> "我把报告生成从单 Agent 汇总升级为三层聚合流水线：**第一层 5 个摘要 Agent 并行独立提炼**（工厂模式防串话，提取核心观点/关键数据/主要结论）；**第二层交叉分析**（去重、标注共识点与分歧点，全部带 Agent 编号）；**第三层主编按固定四层模板合成**（开篇总览 → 分区详解 → 跨 Agent 对比 → 综合结论），每分区标注来源。输出分两部分：先各子 Agent 摘要（快速浏览），后完整报告（深度阅读）。代价是 LLM 调用从 1 次增到 7 次，换来报告的结构化、可追溯、无重复、分歧显式化——这是报告质量与生成速度的经典权衡。"

## 七、风险与权衡（诚实版）

| 风险 | 说明 | 缓解 |
|------|------|------|
| 成本上升 | 7 次 LLM 调用（原 1 次） | 可配置开关：默认流水线，可退回单 Agent 汇总 |
| 延迟增加 | 多 1-2 分钟 | 摘要层并行（不排队）；前端显示"正在聚合"进度 |
| 摘要丢失细节 | 摘要 Agent 压缩原文 | 摘要要求标注可追溯；分区详解可引用原始来源 |
| 交叉分析误判 | 共识/分歧分类可能错 | 主编层仍以原始摘要为准，交叉分析仅作参考 |
| 深度冲突 | 分歧点无法自动裁决 | 报告如实呈现双方说法，不强行统一（诚实 > 一致） |
